## 一、官方契约摘录

### Anthropic — Claude Opus 4.7（[adaptive-thinking](https://platform.claude.com/docs/en/build-with-claude/adaptive-thinking) / [effort](https://platform.claude.com/docs/en/build-with-claude/effort)，2026-06-01 抓取）

1. **adaptive 是 4.7 唯一支持的 thinking 模式**；`thinking:{type:'enabled', budget_tokens:N}` 被 **400 拒绝**。
2. **thinking 默认 off**：不显式 `thinking:{type:'adaptive'}` 则不思考。
3. **`{type:'disabled'}` 对 4.7 合法**，效果 = 不思考（官方"Adaptive vs manual vs disabled"表：Disabled = "Omit thinking parameter or pass `{type:'disabled'}`"，适用除 Mythos Preview 外所有模型）。
4. **`thinking.display` 在 4.7 默认 `'omitted'`**（4.6/4.5 默认 `'summarized'`）。omitted 时 thinking 块 `thinking` 字段为空、仅含 `signature`。原文："To restore summarized thinking text on Opus 4.7, set `thinking.display` to `summarized` explicitly: `{type:'adaptive', display:'summarized'}`"。
5. **`display` 与 `thinking.type:'disabled'` 互斥**（"`display` is invalid with `thinking.type:'disabled'`"）→ 修复时不能无脑给所有 thinking 加 display。
6. `output_config.effort`：`low / medium / high(默认) / xhigh(仅4.7+) / max`。是控思考深度的推荐参数，与 `display` **正交**（一个控深度/是否触发，一个控文本是否返回）。high/max 几乎总思考，低档可能跳过。
7. adaptive 流式仍走 `thinking_delta` 事件（与 manual 一致）；adaptive 自动开启 interleaved thinking，无需 beta header。

### OpenAI — GPT-5.5（[reasoning guide](https://developers.openai.com/api/docs/guides/reasoning) / [gpt-5.5](https://developers.openai.com/api/docs/models/gpt-5.5)，2026-06-01 抓取）

1. `reasoning.effort`（GPT-5.5）：`none / low / medium(默认) / high / xhigh`。
2. **要拿 reasoning summary 必须传 `reasoning.summary:'auto'`**；不传则流式不 emit summary delta（只有 `output_item.added/done type=reasoning` 无 content）。
3. 推荐用 Responses API；流式事件 `response.reasoning_summary_text.delta` / `.done`、`response.reasoning_summary_part.added`。

## 二、逐假设复核（含 v2.2.1 行号）

### H1 — `display` 字段缺失 → 4.7 思考文本被吞　【证实】

- **代码现状**：`packages/model-runtime/src/core/anthropicCompatibleFactory/index.ts:196-213`
  - adaptive 分支：`resolvedThinking = { type: 'adaptive' }`（:203），**无 `display` 字段**。
  - effort 经 `output_config:{ effort }` 传（:209、:236-240），与 display 正交——计划书写作时未提此路径，但它**不取代** display。
  - `bedrock/index.ts:301-313` 同构。
- **官方对照**：4.7 `display` 默认 `omitted` → 即便思考触发，前端只拿到空 thinking 块（仅 signature）。**计划书 H1 命题逐字正确**。
- **修复方向**（design 用）：adaptive/enabled 分支按需补 `display:'summarized'`；**disabled 分支禁止加 display**（官方互斥）。需让 `display` 可由用户配置（默认 summarized 以恢复可见思考）。

### H2 — `enableAdaptiveThinking` 默认禁用思考　【证实，升级】

- **代码现状**：`src/services/chat/mecha/modelParamsResolver.ts:172-184`
  - `if (chatConfig.enableAdaptiveThinking) → {type:'adaptive'}`；否则 `else if (!includes('enableReasoning')) → {type:'disabled'}`。
  - Opus 4.7 extendParams = `['disableContextCaching','enableAdaptiveThinking','opus47Effort']`（`packages/model-bank/src/aiModels/anthropic.ts:30`），**不含 `enableReasoning`** → 命中 disabled 分支。
- **默认值（胜负手）**：`packages/const/src/settings/agent.ts:26-40` `DEFAULT_AGENT_CHAT_CONFIG` **没有 `enableAdaptiveThinking`** → 默认 `undefined`(falsy) → resolver 层产出 `thinking:{type:'disabled'}`。
- **最终请求体修正**：`anthropicCompatibleFactory/index.ts:196` 与 `bedrock/index.ts:301` 只处理 `enabled/adaptive`，`disabled` 会被静默丢弃 → 最终 HTTP body **完全不含 `thinking` 字段**。这与原诊断"Vercel logs 不含 thinking 字段"一致；旧表述"默认发 disabled"只成立于 resolver 中间态。
- **官方对照**：无 `thinking` 或 disabled 都等价于"不思考" → **这是 Opus 4.7 思考块不显示的开箱默认主因**。
- **UI 矛盾点**：`ExtendParamsSelect.tsx:355` 预览 `<Switch checked disabled />`（设计意图=锁定开），但 `chatConfig` 默认值未兑现该意图。
- **修复方向**：给 4.7 类模型的 `enableAdaptiveThinking` 设默认 `true`（store 默认或 resolver 兜底），或对"仅 adaptive"模型直接锁定为 adaptive。
- 📐 **数据流精确化（见 design §2.1）**：resolver 产出的 `{type:'disabled'}` 会被 `anthropicCompatibleFactory:196`（仅处理 enabled/adaptive）**静默丢弃 → 最终 HTTP body 不含 thinking 字段**，逐字吻合原诊断"完全不含 thinking"。
- ⚠️ **Opus 4.6 同样中招**：4.6 也是 adaptive-only（`anthropic.ts:64` extendParams 无 `enableReasoning`），默认同样不思考——上文修复表第二行低估了 4.6，以 design §4.2 为准。

### H3 — slider defaultValue 不写回 store　【证实，范围收窄】

- **机制证实**：`src/features/ModelSwitchPanel/components/ControlsForm/createLevelSlider.tsx:74-85`
  - `resolveValue()`：store 无值时返回 `defaultValue` **仅用于显示**；**无 mount/useEffect 写回**；仅 `handleChange`(onChange) 才 `updateAgentChatConfig`。
  - `Opus47EffortSlider.tsx:9-14` `defaultValue:'high'` 只是 UI 回退。
- **已修部分（当前 HEAD / fork）**：`modelParamsResolver.ts:250-251` `effort` 加了 `|| 'high'` 兜底（commit `0b7821e195 fix: enforce effort default`，对应 `docs/plans/2026-04-20-effort-default-and-manual-mode-tools.md`）。精确 `v2.2.1` tag 仍是 `&& chatConfig.effort`。
- **未修部分**：`opus47Effort`（:254 `&& chatConfig.opus47Effort`）、regular `gpt5_2ReasoningEffort`（:204）仍无 resolver 默认值 → 不拖滑条就不显式发 effort。`gpt5_2ProReasoningEffort` 也无 resolver 默认值，但 OpenAI provider 对 pro 已在 `openai/index.ts:99-101` 强制 `reasoning.effort='high'`；若在 resolver 无脑补 `medium`，会在 `openaiCompatibleFactory/index.ts:1241-1248` 覆盖 provider 的 high，属于潜在回归。
- **注意**：Opus 4.7 走 `opus47Effort` 而非 `effort`，**04-20 对 `effort` 的修复对 4.7 无效**。
- **修复方向**：沿用已验证的 resolver 默认值方案（像 `effort` 那样），优先覆盖 `opus47Effort`；regular `gpt5_2ReasoningEffort` 待抓包决定补 `medium` 还是升 `high`；`gpt5_2ProReasoningEffort` 不应补 `medium`。`createLevelSlider` mount 写回可作为全局根治方案，但影响面更广，需单独评估。

### H4 — GPT-5.5 reasoning 链路　【部分证伪 + 保留抓包裁定】

- **分流正确**：`packages/model-bank/src/aiModels/openai.ts` `gpt-5.5`(:50)→`gpt5_2ReasoningEffort`(:94)；`gpt-5.5-pro`(:111)→`gpt5_2ProReasoningEffort`(:131)。各用各 key，无串配。
- **summary 已设（证伪原假设）**：`providers/openai/index.ts:95-112` 对命中 `prunePrefixes`(:14 含 `'gpt-5'`) 的模型，responses 路径 **无条件注入 `reasoning:{summary:'auto', ...}`**（`azureOpenai/index.ts:149-150` 同）。`gpt-5.5`/`gpt-5.5-pro` 均命中。
- **reasoning 对象构建条件**：`openaiCompatibleFactory/index.ts:1241-1248` reasoning 仅在 `reasoning || reasoning_effort` 为真时发出。
- **流式渲染存在**：`responsesStream.ts:121-132` 正确处理 `reasoning_summary_part.added` / `reasoning_summary_text.delta`。
- **归因修正**：regular GPT-5.5 不显示思考块仍可能与 H3 有关（不拖滑条 → 不显式发 effort → OpenAI 默认 medium，简单题可能 skip thinking），但因为 `summary:'auto'` 已存在、UI 默认也显示 medium，"补 medium"只是显式化，不足以证明能修复。椰椰"拖动滑条后思考块出现"更像是高 effort 或用户交互后实际值变化导致，需要 raw body 裁定。
- **Pro 特例**：GPT-5.5 Pro 当前 provider 已强制 high；旧计划中 `gpt5_2ProReasoningEffort` 加默认 medium 的建议是错误的，除非同步改成 high 并确认不会覆盖 provider 特例。
- **⚠️ 静态分析与现象的矛盾（必须抓包裁定）**：即便不拖滑条，handlePayload 仍注入 `reasoning:{summary:'auto'}`（无 effort），理论上 default medium 应思考并返回 summary。"不拖就完全无思考块"需 raw body 确认：是 medium 对该 prompt skip、还是 `responsesAPIModels`(:33) 路由/effort 注入实际路径不同。

## 三、全局根因模型（计划书写作时缺失的洞察）

**Opus 4.7 思考块不显示 = 两层独立 bug 叠加，非单点：**

```
开箱默认
  └─ H2: enableAdaptiveThinking 无默认(falsy) ──► resolver 产出 disabled ──► factory 丢弃 disabled ──► HTTP body 无 thinking ──► 4.x 默认不思考 ──► 无思考块
用户手动开 adaptive 后（绕过 H2）
  └─ H1: adaptive 分支不带 display:'summarized' ──► 4.7 默认 omitted ──► thinking 块为空(仅 signature) ──► 仍看不到思考文本
  └─ H3: opus47Effort 不写回 ──► 无 output_config.effort ──► 退化为 default high（思考强度问题，非阻塞）
```

→ **修 H2 让它思考、修 H1 让思考可见，缺一不可**；H3 是强度/体验层。GPT-5.5 的 summary 链路已存在，默认 effort 是否应显式化或升 high 必须由抓包决定；GPT-5.5 Pro 不应按旧方案补 medium。
